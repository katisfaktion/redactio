# Review and Approved Export Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let users inspect and correct redactions, bind approval to exact current bytes, and export only verified approved documents.

**Architecture:** The host reads private review records and revalidates sources before showing original text. P2 renders corrected output; P3's journal commits output/review/mapping together. Vue uses plain text and offset-derived highlights, with no HTML execution.

**Tech Stack:** Existing Vue/Onyx/TypeScript, Rust/serde/storage, Python renderer; browser Range/Selection and native text rendering.

**Spec:** [Approved release](../specs/2026-09-19-redactio-initial-release-design.md), sections 3.3/3.4, 4.2, 5/6/9/11. Depends on P3 and [contracts C1–C3](2026-09-19-00-release-overview.md#shared-contracts-to-implement).

## Global Constraints

- “Offsets are zero-based Unicode code-point positions with an exclusive end.”
- “Empty extraction cannot be approved.”
- “Any regeneration invalidates approval.”
- “Local review notes remain in protected metadata because notes can themselves contain identifying information.”
- “Export one pair per action; combining pairs into a flat directory is outside this release because document filenames can repeat across pairs.”
- “The smallest initial behavior requires an empty destination, avoiding merges or silent replacement of older exports.”
- All [overview constraints](2026-09-19-00-release-overview.md#global-constraints) apply. A status-only approval save is an explicit review decision rendered through the journal; editing detections/body always invalidates an earlier approval before a new decision.

## Review Focus

1. An old approved flag survives changed source/settings/output: bind all identities/hashes and recheck in P4.1/P4.3.
2. Emoji or nested marks shift a manual selection: code-point conversion tests in P4.2.
3. The source contains HTML, remote images, or literal placeholders: text-only rendering and known-span highlighting in P4.2.
4. Unsaved edits are lost on pair/document switch or app close: dirty navigation guard tests in P4.2.
5. Export succeeds for one file but fails for another: report the exact partial result and never overwrite unrelated destination entries in P4.3.

fn approval_never_transfers_to_new_bytes_or_another_pair() {
    let saved = ApprovalBinding {
        key: DocumentKey { sync_pair_id: uuid::Uuid::new_v4(), doc_id: "doc-0001".into() },

- [ ] Implement the conversion with bounds and surrogate validation:

```ts
export function codePointOffset(text: string, offset: number): number {
  if (!Number.isInteger(offset) || offset < 0 || offset > text.length) throw new RangeError();
  const before = text.charCodeAt(offset - 1), after = text.charCodeAt(offset);
  if (before >= 0xd800 && before <= 0xdbff && after >= 0xdc00 && after <= 0xdfff) {
    throw new RangeError("Selection splits a code point");
  }
  return Array.from(text.slice(0, offset)).length;
}
```

For selections spanning nested marks, build a Range from container start to each
endpoint and count its text; ensure both endpoints are inside the original-text
container, normalize backward selections, and reject empty ranges. The selectable
container contains text/mark nodes only; labels/confidence controls live outside
it so Range text matches the engine coordinate space.
